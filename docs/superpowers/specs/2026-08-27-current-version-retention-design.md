# 当前版本唯一保留制设计

## 目标

系统只保留并展示每场比赛、每个模型、每个竞赛账户下符合当前 `PromptContract` 的最新预测。删除被替代或协议过期的预测，以及它们关联的模拟下注、比赛结算和资金流水，避免当前 `no_bet` 与旧持仓同时出现。

当前协议版本以 `DEFAULT_PROMPT_CONTRACT.version` 为唯一来源，禁止在清理逻辑中重复硬编码版本字符串。

## 当前版本判定

预测按 `(competition_id, fixture_id, model_key)` 分组：

1. 只把 `ai.prompt_version == DEFAULT_PROMPT_CONTRACT.version` 的记录视为兼容版本。
2. 兼容记录超过一条时，只保留按 `created_at`、`id` 排序后的最新一条。
3. 没有兼容记录时，该分组没有当前预测，不使用旧协议记录补位。
4. 当前预测关联的下注、结算和资金流水可以保留；其他记录均属于待清理历史版本。

## 数据清理

仓储层提供同一套“预览”和“执行”逻辑，预览返回各表待删除数量及受影响账户，不修改数据。执行必须在单个数据库事务内完成，并遵循以下顺序：

1. 确定所有待删除预测 ID 和关联下注 ID。
2. 删除引用旧下注的 `bankroll_transactions`。
3. 删除旧预测对应的 `fixture_settlements`。
4. 删除旧预测对应的 `bets`。
5. 删除旧 `predictions`。
6. 删除不再被任何保留预测引用的孤立 `evidence_snapshots`。
7. 为受影响的 `(competition_id, model_key)` 账户按 `simulation_accounts.initial_balance` 和保留账本重新计算每条流水的 `balance_after`。

清理接口必须幂等：首次执行后再次预览和执行，待删除数量都应为 0。任何步骤失败时整个事务回滚。

## 写入时保留策略

一次性清理后，新预测成功保存及其模拟下注处理完成时，对同一 `(competition_id, fixture_id, model_key)` 分组执行相同压缩规则，防止历史版本再次积累。压缩只影响模拟账户，不连接或修改真实投注平台。

## API 行为

比赛详情只查询当前协议版本的最新预测。下注只通过 `bet_for_prediction(current_prediction.id)` 返回，删除按比赛和模型查找任意旧下注的回退逻辑。

没有当前预测时返回 `null`，前端显示“暂无当前版本预测”。`no_bet` 或 `insufficient_data` 的当前预测不得通过历史记录显示持仓。

管理清理能力分为预览和执行两个受现有管理鉴权保护的操作。执行响应返回实际删除数量、受影响账户和重算结果，不返回已删除记录内容。

## 页面行为

删除以下历史兼容分支和文案：

- “历史模型概率已保留”
- “历史提示词”
- “历史版本持仓”
- “早期预测已经执行，当前建议不会追溯撤单”

预测面板只展示当前预测及其直接关联的模拟仓位。模型标签没有当前预测时展示空状态，不复用旧概率或旧账单。

## 安全与错误处理

- 实际执行前必须先取得并记录预览数量。
- 清理按明确 ID 集合执行，不使用模糊时间范围或全表无条件删除。
- 保留用户现有工作区修改，不改动与本任务无关的数据源、预测数学和下注阈值。
- 清理失败时返回错误并保持数据库原状；余额重算不完整时不得提交事务。

## 验证

后端测试覆盖：当前版本判定、旧协议删除、同版本重复记录压缩、依赖删除顺序、余额重算、事务回滚、幂等性，以及不同竞赛账户隔离。

API 契约测试覆盖：详情页不回退历史下注、`no_bet` 不返回持仓、没有兼容预测时返回空状态，以及清理预览/执行计数一致。

前端测试或类型检查覆盖：历史文案和历史持仓分支不存在，当前下注仍正常展示。最终运行完整 API 测试、前端 lint、TypeScript 检查和生产构建，并用皇马比赛验证当前 `no_bet` 页面不再出现旧下注。

## 非目标

- 不降低 `no_bet` 标准。
- 不修改预测概率或赔率价值算法。
- 不保留供页面回退使用的历史版本。
- 不接入真实投注平台。
