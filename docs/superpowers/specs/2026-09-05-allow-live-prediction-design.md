# 允许已开球比赛预测设计

## 背景

当前预测接口和前端操作台只允许 `scheduled` 且开球时间未到的比赛。这样会拒绝已经进入 `live` 状态的比赛，也会拒绝状态同步滞后但开球时间已过的 `scheduled` 比赛。需求是：比赛已开球仍可生成预测，比赛完场后不可再生成预测。

## 目标与边界

- `scheduled`（无论开球时间是否已过）和 `live` 比赛允许手动生成或重新生成预测。
- `finished` 比赛禁止生成或重新生成预测，并由后端返回 HTTP 409。
- `postponed`、`cancelled` 等非可进行状态继续禁止预测。
- “可生成预测”与“可产生模拟下注”保持独立：模拟下注仍只允许开球前的 `scheduled` 比赛，赛中预测不产生新模拟单。

## 方案

在 FastAPI 主模块增加一个局部资格判断，集中表达预测创建的状态规则：状态为 `scheduled` 或 `live` 即可，不再用开球时间作为预测创建的阻断条件；其他状态拒绝。预测创建接口调用该判断，保留现有数据上下文和管理员鉴权流程。

前端复用同等规则更新 `canCreatePreMatchPrediction`。详情页在 `scheduled`（包括已过开球时间）和 `live` 状态显示同步、预测和重新生成操作；完场及延期/取消状态隐藏这些操作。按钮文案仍使用现有“发起预测/重新生成”，避免扩大界面范围。

`BankrollService` 的 `_fixture_started` 和现有 `status == scheduled` 检查不变，确保赛中只保存预测版本，不会因为接口放开而产生模拟下注。

## 错误处理

- 后端对不具备预测资格的状态返回现有 409 错误契约。
- 前端通过详情中的状态隐藏不可用操作；若状态在页面打开后发生变化，接口 409 仍由现有错误展示流程处理。

## 测试

- 后端新增/调整接口测试，覆盖未来 `scheduled`、已过开球时间的 `scheduled`、`live` 和 `finished`。
- 对 `live` 预测验证请求成功且没有新增模拟下注。
- 对 `finished` 验证接口返回 409。
- 前端至少运行现有 TypeScript/ESLint 检查，确保状态判断改动无类型错误。

## 不在本次范围

- 不改变自动预测任务的赛前调度窗口。
- 不允许赛中或完场比赛产生、修改或重算模拟下注。
- 不改动比赛状态同步、结算或历史回填规则。
