# 双模型左侧 Tab 预测布局设计

## 目标

把比赛详情中的 DeepSeek 与 GPT-5.6 Sol 并排预测卡改为单内容区切换，减少横向拥挤，同时保留两个模型的独立判断、模拟账户与历史仓位信息。

## 桌面布局

- 预测区域标题、说明和统一的“手动生成”按钮保持在顶部。
- 主体使用两列布局：左侧为固定宽度的模型 Tab，右侧为选中模型的完整 `ProbabilityPanel`。
- 左侧依次显示 DeepSeek、GPT-5.6 Sol；默认选中 DeepSeek。
- 每个 Tab 显示模型名、胜平负判断、投资状态，以及当前仍存在的模拟仓位金额。
- 当前 Tab 使用对应模型的品牌强调色、左侧状态条和清晰的选中态；未选中 Tab 保持安静、可扫描。
- 右侧沿用现有完整预测内容，包括概率、综合评估、风险、盘口、本次建议和历史版本仓位。

## 交互

- 点击 Tab 仅切换本地显示状态，不重新请求模型、不改变预测、不创建或撤销仓位。
- 统一“手动生成”按钮仍并行生成两个模型的最新预测。
- 如果只有一个模型有预测，只显示该模型并自动选中；另一个模型不展示空白内容卡。
- 数据刷新后，如果当前模型仍存在则保持选择；否则切换到第一个可用模型。

## 移动端

- 在窄于 820px 的视口中，左侧竖向 Tab 转为预测内容上方的横向双 Tab。
- Tab 保留模型名和下注状态，隐藏次要摘要以避免文字挤压。
- 完整预测面板保持单列，不产生页面级横向滚动。

## 可访问性

- 模型导航使用 `role="tablist"`、`role="tab"`、`role="tabpanel"`。
- 支持方向键切换：桌面使用上下键，移动端同时接受左右键；Home/End 跳到首尾模型。
- Tab 提供 `aria-selected`、`aria-controls`，内容面板提供对应 `aria-labelledby`。
- 键盘焦点与视觉选中态必须明确区分。

## 数据与资金语义

- 不修改 API、数据库、预测或结算逻辑。
- “本次模型建议”和“历史版本持仓”继续分开展示，避免把最新 `no_bet` 与旧的已执行仓位混为一谈。
- Tab 中的仓位金额来自该模型对当前比赛已存在的仓位，不代表最新预测仍建议下注。

## 验证

- ESLint、TypeScript 与 Next.js 生产构建通过。
- 验证两家模型可切换，右侧内容、模型标签、建议和仓位随 Tab 正确对应。
- 验证桌面竖向布局与移动横向布局不产生页面级溢出。
- 验证键盘 Tab、方向键、Home、End 操作。
