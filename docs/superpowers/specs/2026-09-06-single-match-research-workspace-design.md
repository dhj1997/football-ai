# 单场研究报告工作台设计

## 背景

当前产品已经具备赛程、近期状态、历史交锋、伤停、首发、赔率、双模型预测和模拟绩效，但信息组织仍偏向“把已有模块放到页面上”。用户需要它进化为更成熟的足球产品，并指定参考雷速体育与懂球帝。

本轮不复制两家产品的内容门户、社区或全量即时比分能力，而是吸收其成熟的信息组织方式：雷速体育的高密度赛程扫描和数据分类，懂球帝清晰的比赛头部与上下文导航。产品继续以“可追溯的比赛研究报告”为差异化核心。

## 已确认方向

- 产品定位：专业比赛研究台。
- 主布局：单场研究报告优先。
- 运行范围：只完成本地实现和本地服务验证，不上传服务器。
- 预测规则：未开赛和进行中的比赛可以生成预测；完场后只能查看已有预测，不能新生成。

## 目标

1. 用户进入单场详情后，10 秒内看懂比赛状态、模型方向、证据质量和最大风险。
2. 首页仍能快速定位比赛，但不与成熟比分平台竞争全量联赛和分钟级事件流。
3. 模型结论、数据缺口、来源与时间并列展示，避免把部分数据包装成完整判断。
4. 桌面和移动端使用同一信息顺序，移动端只重排，不删除关键证据。
5. 保留现有赛程、预测、模拟投注、管理台和数据同步契约。

## 非目标

- 不增加新闻流、评论、社区、视频、收藏提醒或登录体系。
- 不新增第三方数据源，不实现比赛事件时间线、文字直播或动画直播。
- 不伪造近期五场、赔率走势、伤停或首发；供应商不足时展示明确缺口。
- 不自动运行模型，不改变当前定时数据同步策略。
- 不重写后端架构或进行与本轮体验无关的重构。

## 信息架构

### 赛程入口

首页是研究报告索引，不是内容门户。顶部保留全局导航，主体提供以下时间入口：

- 昨日：快速回看刚结束的比赛。
- 今日：默认入口，优先显示进行中和即将开始的比赛。
- 明日：查看下一比赛日。
- 未来 7 天：使用已缓存的七天赛程窗口。
- 历史：保留现有历史查询入口，作为次级操作。

联赛筛选继续支持全部、英超、西甲、中超和足协杯。比赛按联赛分组，每行稳定展示开球时间或比赛分钟、状态、双方、比分、首发状态、证据就绪数和是否已有预测。状态排序为进行中、即将开始、未开始、完场、延期/取消。

列表只返回轻量摘要，不把完整阵容和证据文档塞入列表响应。新增摘要字段应包括：证据就绪数、证据总数、缺失项、证据更新时间和当前预测是否存在。

### 单场研究报告

详情页按以下顺序组织：

1. 比赛头部：联赛、轮次、双方队徽和名称、开球时间或比分、比赛状态、场地。
2. 决策摘要：模型共识、证据质量、关键变量、盘口观察。
3. 主要概率：双模型结果并列，存在模型分歧时明确提示，不合成虚假的统一结论。
4. 关键判断因子：从现有结构化证据确定性派生，不调用新模型生成文案。
5. 证据状态表：显示每项数据的数量、状态、来源、更新时间和缺失原因。
6. 预测操作带：未开赛或进行中可生成；完场禁用并解释原因。
7. 深层页签：模型分析、近期状态、历史交锋、阵容伤停、赔率走势、球队资料。

“决策摘要”是默认页签。深层页签用于核对依据，不与首屏争夺注意力。

## 决策摘要规则

摘要只组合已有确定性数据，不新增不可审计的 AI 文案。

### 模型共识

- 两个模型都有结果且最高概率方向相同：显示“方向一致”，并展示共同方向。
- 两个模型都有结果但方向不同：显示“存在分歧”，分别列出方向和概率。
- 只有一个模型有结果：显示“单模型结果”。
- 没有模型结果：显示“待生成”。

进行中生成的预测必须标注生成时的比赛状态、比分和比赛分钟；若当前后端尚无分钟字段，则至少记录状态、比分和生成时间，不推测分钟。

### 证据质量

固定检查六项：近期状态、历史交锋、伤停/可用阵容、确认首发、赛前赔率、模型结果。每项同时显示文字状态，不只依赖颜色。总览展示 `n / 6`，并列出缺失项。

### 关键变量

按以下优先级选取最多三项：

1. 首发是否确认，以及核心可用球员差异。
2. 双方近期每场积分差异。
3. 已知伤停人数和关键缺阵球员。
4. 主客队战力保留差异。
5. 历史交锋样本方向。

没有足够数据时显示“证据不足”，不输出倾向。

### 盘口观察

展示当前 1X2、亚洲让球和最后更新时间。若有初始与当前盘口，显示方向变化；只有一个快照时只显示当前值。超过现有赔率新鲜度阈值时标记“需刷新”，不使用“稳定”等未经时间序列支持的词。

## 页面状态

### 未开赛

- 展示倒计时或开球时间。
- 可以生成预测。
- 首发未确认时显示下一次刷新窗口。

### 进行中

- 显示进行中状态和当前比分。
- 可以基于当前已知状态生成预测。
- 操作带明确说明预测包含赛中信息，不能与纯赛前版本混为一谈。

### 完场

- 显示最终比分和已有预测表现。
- 禁止新预测。
- 仍可查看完整证据、历史模型版本和结算结果。

### 数据部分缺失

- 页面保持可用，每个缺失模块显示具体缺口。
- 证据状态表是唯一总览来源，避免多个相互矛盾的“就绪”状态。
- 请求失败保留最近成功快照并显示陈旧时间。

## 视觉系统

延续当前冷白纸面、深球场绿和信号黄，但降低“后台仪表盘”感，形成更像比赛档案的研究报告。

- 页面主体使用连续分区和细边线，不使用卡片套卡片。
- 比赛头部是首屏主体，但高度克制，下一段决策摘要必须在首屏露出。
- 概率使用数字、标签和短条共同表达；红蓝仅用于风险和对比系列。
- 控件圆角不超过 6px，按钮高度不低于 44px，所有图标按钮提供工具提示和可访问名称。
- 字距固定为 `0`；固定数据使用表格数字；不按视口宽度缩放字号。
- 尊重 `prefers-reduced-motion`，加载和切换不引发布局跳动。

### 桌面端

内容最大宽度约 1280px。比赛头部横向排列双方和中央状态；决策摘要为四列连续信息带；主内容使用约 5:3 的两栏结构，左侧概率/模型，右侧关键因子/证据状态。

### 移动端

按比赛头部、决策摘要、概率、关键因子、证据状态、操作带顺序单列排列。页签横向滚动；双方队名允许换行；固定比分区宽度，避免长队名挤压比分。

## 组件边界

现有 `fixture-workspace.tsx` 已超过一千行。本轮只拆出与详情报告直接相关的组件，不进行全面重构：

- `MatchReportHeader`：比赛身份和状态。
- `DecisionSummaryStrip`：四项决策摘要。
- `ModelConsensusPanel`：双模型方向和概率。
- `KeyFactorsPanel`：结构化关键变量。
- `EvidenceStatusTable`：统一数据状态、来源和时间。
- `MatchReportTabs`：深层证据导航。

赛程列表继续留在现有工作区组件中。派生摘要使用无副作用的纯函数，便于单元测试。

## API 与数据契约

### 赛程查询

扩展日期筛选以支持昨日和未来七天。后端继续从本地缓存读取，不因页面请求触发全量第三方同步。推荐新增稳定枚举：`yesterday`、`today`、`tomorrow`、`upcoming`、`history`。

### 赛程摘要

每场列表项补充可选的轻量字段：

```text
evidence_summary.ready_count
evidence_summary.total_count
evidence_summary.missing
evidence_summary.updated_at
has_prediction
```

旧客户端忽略新增字段即可，现有字段不改名。

### 预测权限

前端与 API 使用同一规则：`scheduled` 或 `live` 可生成，`finished`、`postponed`、`cancelled` 不可生成。API 是最终权限边界，前端只负责展示。

所有新增或重组的球员输出继续经过 `to_chinese_player_name`；前端不得直接展示供应商英文球员名。

## 测试与验收

### 后端

- 日期筛选正确返回昨日和未来七天，且不越过缓存窗口。
- 列表摘要只包含轻量状态，不泄露完整阵容文档。
- 预测权限覆盖 `scheduled`、`live`、`finished` 三条关键路径。

### 前端

- 决策摘要覆盖双模型一致、分歧、单模型和无模型四种状态。
- 证据质量在字段缺失和完整时计算正确。
- 完场按钮不可用；进行中按钮可用并有明确说明。
- 长队名、空赔率、空交锋和未确认首发不导致布局溢出。

### 视觉验收

- 本地桌面宽屏和移动端截图检查。
- 首屏可见比赛身份、状态和至少一部分决策摘要。
- 页面无重叠、横向溢出、空白画布或布局跳动。
- 键盘可遍历页签和操作按钮，焦点清晰。
