# 比赛详情球员中文名补全设计

## 问题

比赛详情会把未命中静态别名且没有缓存音译的球员显示为“待核验球员”。现有
`PlayerNameService` 已支持批量中文音译、双模型回退和数据库缓存，但详情接口只读取
缓存，不会为首次出现的球员生成中文名。

## 方案

在比赛详情组装完免费球队阵容后，调用现有 `PlayerNameService.enrich` 时启用
`resolve_missing=True`。服务先使用人工别名和已有缓存，只将仍未解析的供应商姓名按批次
送入已配置的音译服务，并保存结果。随后继续由 `public_payload` 清除供应商原名，保证 API
和页面只展示中文名称。

不把补全移动到赛程或证据同步任务，因为这会扩大共享同步链路的改动范围；也不只扩充静态
别名表，因为它无法覆盖后续新增球员。

## 失败处理

音译服务不可用或返回无效结果时，沿用现有安全占位名称并在 `context.player_name.error`
记录失败原因。不得回退展示供应商英文名。成功结果写入缓存，后续详情请求不重复调用模型。

## 验证

增加一个接口级回归测试，确认比赛详情对缺少中文别名的球员启用名称补全，并在公开响应中
返回生成的中文名且不包含供应商原名。运行该测试及现有球员名称服务测试。
