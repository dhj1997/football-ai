# 球员中文名与置信度重复否决回归修复设计

## 目标

修复明日比赛中大量球员统一显示“待核验球员”，以及 AI 已明确建议下注、赔率优势为正时仍被固定置信度门槛重复否决的问题。

保持以下边界不变：

- 首发未确认只是不确定性提示，不是绝对 `no_bet` 条件。
- DeepSeek 与 GPT 独立预测、独立账户、独立仓位和收益。
- 后端继续负责赔率新鲜度、正优势、数据完整性、市场匹配和账户风控。
- 不降低 3% 正优势门槛，不使用首发未确认小仓位，不强制产生下注。
- 不展示供应商英文球员名，不接入授权不明确的数据源。

## 已验证根因

明日五场比赛约 272 名当前展示球员中，只有 1 名命中已有人工中文别名。其余球员虽然仍有稳定供应商 ID、号码、位置和统计数据，但因英文名边界被统一替换为“待核验球员”，页面看起来像球员信息丢失。

明日十个模型预测的 `lineup_unconfirmed` 均只存在于警告中，没有参与最终否决。全部 `no_bet` 来自负优势、AI 自主 `no_bet`、模型调用失败，以及固定 60% 置信度门槛。部分 AI 已明确输出 `bet` 且优势超过 3%，仍被市场层和资金层重复使用的置信度门槛拦截。

## 方案选择

采用“缓存式机器中文音译 + 唯一待核验标签”，同时将完成态 AI 的低置信度从硬否决改为警告。

未采用：

- 仅扩充人工别名：无法及时覆盖当前和未来的新阵容。
- 仅在线查询 Wikidata：其结构化数据为 CC0，且存在 ESPN FC ID 属性，但覆盖和本地网络稳定性不足，不能作为本次唯一方案。
- 直接降低置信度数值到 55%：阈值仍然武断，也继续与 AI 的结构化 `bet/no_bet` 重复判断。

## 球员名称解析

名称优先级固定为：

1. 人工审核中文别名；
2. 按稳定球员 ID 缓存的机器中文音译；
3. 唯一待核验标签。

机器音译只处理当前没有人工别名的拉丁字母球员名。使用项目已经授权配置的模型服务进行批量音译，不查询或抓取新的足球网站。输出只包含输入球员 ID 与中文音译，不允许补充身价、国籍、能力或其他事实。

每条缓存记录包含：

- `canonical_player_id`；
- `provider_player_id`；
- `source_name_hash`；
- `chinese_name`；
- `name_source`，例如 `deepseek_transliteration`；
- `name_status=machine_translated`；
- `created_at` 和模型版本。

缓存只在源名称哈希变化时重新生成。人工别名始终覆盖机器音译。机器音译失败、缺失或校验不通过时，不展示英文名，改为带号码、位置或稳定 ID 后四位的唯一标签，例如“待核验球员 #10（前锋）”或“待核验球员 7A3F（中场）”。

所有最终名称仍必须经过 `to_chinese_player_name`。公共 API 可以返回 `name_status` 和 `name_source`，但不能返回供应商 `original_name`。

### 音译校验

批量音译结果必须满足：

- 输入 ID 与输出 ID 一一对应；
- 中文名称包含汉字，不含供应商英文原名；
- 不接受空值、“未知”“待核验”等泛化结果；
- 同一批中异常大量重复名称时整批拒绝；
- 失败时保持现有缓存或唯一待核验标签，不伪造结果。

## 数据流

球员名称解析拆为两个阶段：

1. 球队或证据同步后收集新的未解析球员，批量生成并持久化机器音译缓存。
2. API、模型输入、页面和日志输出前，从缓存补充名称，再执行现有身份关联与 `to_chinese_player_name` 边界。

预测请求不得为每名球员单独调用模型。每批最多处理固定数量的新名称，已有缓存不重复调用。单次名称解析失败不能阻塞比赛证据、预测或页面加载。

实现后运行一次当前缓存球员的受控补全任务，再重新生成明日比赛当前预测。旧预测及旧模拟单继续遵循当前版本替换规则，不形成重复仓位。

## 下注决策边界

AI 的结构化 `bet/no_bet` 负责主观判断和预测信心，后端负责客观市场与风险校验。

### 完成态 AI 推荐 `bet`

当 AI 状态为 `completed` 且明确输出 `bet`：

- `forecast_confidence < 0.60` 写入 `warning_codes=[low_confidence]`；
- 低置信度不再单独把状态改为 `no_bet`；
- 仍必须通过 3% 正优势、赔率新鲜度、市场匹配、最低数据完整度和账户风险检查；
- 通过后使用现有正常仓位算法，不增加小仓位折扣。

### AI 推荐 `no_bet` 或模型失败

- AI 明确 `no_bet`：保留 `ai_no_bet` 硬原因，后端不得下注。
- AI 未配置、失败或输出无效：保留 `low_confidence`/数据缺失硬原因，不允许 Poisson 自动替代下注。
- 负优势、赔率过期、无匹配市场、严重数据不足和风险超限继续硬否决。

资金层只执行市场层最终 `decision.status=bet`，删除重复的 60% 置信度判断，避免同一规则在两层产生不一致。

## 页面

球员区域继续展示关键可用、关键缺阵、预计替补、预计分钟和贡献。机器音译名称旁显示紧凑的“自动音译”状态；唯一待核验标签必须带号码、位置或稳定短 ID，避免多行完全相同。

执行决定区明确分开：

- AI 观点；
- 后端硬阻断原因；
- 不确定性警告。

低置信度只出现在警告区时，页面不得仍显示为后端阻断原因。

## 测试与验收

1. 人工别名优先于机器音译缓存。
2. 未解析英文名能够使用有效的缓存中文名，公共 API、模型输入和日志不出现供应商英文名。
3. 音译失败时显示唯一待核验标签，不能让整支球队所有球员同名。
4. 已完成 AI 推荐 `bet`、正优势、赔率新鲜、数据和风控通过时，即使置信度低于 60% 也能按正常算法下注。
5. AI `no_bet`、负优势、过期赔率、无市场、严重数据不足和模型失败仍不能下注。
6. `lineup_unconfirmed` 与完成态 `low_confidence` 只显示为警告。
7. 资金层不再用第二套置信度门槛否决市场层的 `bet`。
8. 当前预测替换旧单，两个模型账户互不影响。
9. 运行风险相称的单元测试、API 契约测试、完整 API 测试、前端 lint、TypeScript 和生产构建。
10. 用明日真实缓存比赛验证球员信息、AI 观点、后端原因、正常仓位、桌面和移动端无页面级横向溢出且控制台无错误。

## 非目标

- 不把机器音译当作人工审核或权威官方中文名。
- 不抓取 Transfermarkt 或其他授权不明确的足球网站。
- 不降低正优势、赔率新鲜度、数据完整性和账户风险规则。
- 不连接真实投注平台。
- 不为增加下注数量而修改 AI 的 `no_bet` 输出。
