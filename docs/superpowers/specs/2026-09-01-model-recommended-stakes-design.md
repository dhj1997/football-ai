# 模型建议仓位执行设计

## 目标

取消固定 `1%` 单场下注请求金额，让 GPT 和 DeepSeek 的模拟执行金额按各自决策中的理论仓位计算。模型建议仓位通常为 `10%` 至 `25%`，最终金额仍必须通过组合风险门禁。

## 执行规则

1. 预测层继续计算并保存 `decision.stake_fraction`，作为该模型对当前候选的理论仓位。
2. Portfolio 候选携带该理论仓位；Risk Gate 以“账户净值 × 理论仓位”作为请求金额。
3. 单场上限提高为 `25%`，与现有模型建议仓位上限一致。
4. 每日敞口 `5%`、单联赛当日敞口 `2%`、总敞口 `10%` 和最大回撤 `30%` 保持不变，任何上限优先于模型建议仓位。
5. 缺失、非法或为零的理论仓位回退到配置中的基础仓位；基础仓位改为 `10%`，避免新旧预测结构导致下注金额为零。

## 数据流与边界

- `market_decision` 负责给出理论仓位，不负责决定组合最终金额。
- `portfolio` 负责把理论仓位传递给候选和 Risk Gate。
- `bankroll` 负责执行、落账和展示最终 `allowed_stake`。
- 这是模拟下注，不改变真实资金，不回溯修改已经落账的历史下注。

## 验证

- 单元测试验证理论仓位进入请求金额，并验证每日、联赛、总敞口仍能截断金额。
- 回归测试验证旧预测没有 `stake_fraction` 时使用 `10%` 基础仓位。
- API 验证 GPT 账户新下注金额不再固定为 `1%`，并保留风险门禁字段。
