# 手动预测状态与错误反馈设计

## 目标

让比赛详情页的手动预测入口与比赛状态一致：未开始比赛可以首次生成或重新生成预测，完场、进行中、延期和取消比赛不能生成预测。用户点击后必须看到加载、成功或中文错误反馈，不能出现无响应。

## 状态矩阵

| 比赛状态 | 当前预测 | 页面行为 |
| --- | --- | --- |
| `scheduled` | 无 | 在空状态中显示“手动生成预测”按钮 |
| `scheduled` | 有 | 在模型预测区显示“重新生成”按钮 |
| `finished` | 任意 | 不显示按钮，显示“比赛已结束，不能重新预测” |
| `live` | 任意 | 不显示按钮，显示“比赛进行中，不能生成赛前预测” |
| `postponed` | 任意 | 不显示按钮，显示“比赛已延期，等待新赛程后再预测” |
| `cancelled` | 任意 | 不显示按钮，显示“比赛已取消，不能生成预测” |

后端继续只接受 `scheduled`，其他状态返回 `409`，前端状态判断不能替代后端校验。

## 手动预测入口

比赛详情页复用现有 `runManualPrediction` 方法和按钮样式，不新增第二套请求逻辑。无当前预测时，空状态接收 `onManualPredict` 与 `predicting`，在 `scheduled` 状态渲染真正的按钮。已有预测时保留模型区按钮，文字改为“重新生成”。

按钮请求期间禁用并显示“计算中”。请求完成后重新加载比赛详情；成功显示双模型预测标识，失败显示页面顶部中文错误。

## 代理与错误契约

Next.js `/api/admin/predict` 代理按以下顺序确定 API 地址：

1. `API_BASE_URL`
2. `NEXT_PUBLIC_API_BASE_URL`
3. `http://127.0.0.1:8000`

代理正常转发上游 HTTP 状态和 JSON 错误。连接失败、超时或上游返回非 JSON 时，代理返回 `502` 和稳定中文 JSON：`{"detail":"预测服务暂时不可用，请稍后重试"}`，避免 Next.js 空白 `500`。

本地 `3002` 验证服务必须在启动时设置 `API_BASE_URL=http://127.0.0.1:8001`，与当前 API 实例一致。

## 验证

- 路由测试：地址优先级、上游 `409` 透传、连接失败返回中文 `502`。
- 组件行为：`scheduled` 无预测显示首次生成按钮；`finished` 不显示按钮并展示明确原因。
- 前端 lint、TypeScript 检查和生产构建通过。
- 浏览器验证皇马完场页面没有手动预测按钮，显示“比赛已结束，不能重新预测”。
- 使用一场未开始的测试比赛验证按钮可点击、显示加载状态，并能呈现成功或后端中文错误。

## 非目标

- 不允许完场后补生成预测。
- 不修改模型提示词、概率、下注标准或历史记录策略。
- 不连接真实投注平台。
