# 懂球帝赔率与赛事数据同步设计

## 目标

将懂球帝作为独立数据源接入现有足球分析系统，补充以下数据：

- 赛事与赛程
- Bet365 和皇冠的欧指、让球初始值与即时值
- 赛前分析、交锋历史、近期战绩、积分和攻防对比
- 球队资料、教练、工作人员、球员阵容和球队赛程

数据进入现有缓存、证据快照和赔率快照后，赛前分析只读取本地数据，不在页面请求期间等待远程数据。

## 数据流与任务边界

懂球帝使用独立 provider，不修改现有 API-Football、ESPN 和 TheSportsDB provider。

1. 赛程任务按中国时区每天同步一次。服务启动时检查当天成功标记；当天已成功同步则不再重复请求，失败可在当天重试。
2. 赛程入库后，为新比赛排队执行一次赔率和赛前分析同步。
3. 开赛前 50 分钟执行一次临场赔率和赛前分析同步，以完成标记保证幂等；服务短暂不可用时允许在临近窗口重试。
4. 球队资料在首次遇到懂球帝球队 ID 时同步一次，写入数据库后只读复用。缺失资料时的单场手动同步可以补齐，但不主动周期刷新。
5. 页面只读取数据库缓存。管理页支持同步懂球帝赛程，比赛详情页支持同步当前比赛的赔率与赛前分析。

## 源接口

主要接口为懂球帝前端当前使用的 JSON 接口：

- 比赛列表：`/magicball/v1/list/match_list`
- 比赛详情：`/magicball/v1/match/app/detail`
- 指数：`beta-sport-data.../soccer/biz/dqd/v1/match/odds/index/{match_id}`
- 赛前分析：`beta-api.../data/match/pre_analysis_v1/{match_id}`
- 攻防对比：`beta-sport-data.../soccer/biz/dqd/match/pre_analyze_data_contrast/{match_id}`
- 交锋雷达：`beta-sport-data.../soccer/data/match/h2h`
- 球队资料：`/api/data/v1/detail/team/{team_id}`
- 球队阵容：`/sport-data/soccer/biz/dqd/v1/team/member_v2/{team_id}`

这些是前端内部接口，不承诺公开 SLA。实现使用低频 HTTP 请求、缓存、有限重试和字段校验，不绕过验证码、登录限制或付费内容。

## 赔率模型

指数接口只保留两个供应商：

- `area=36` / `cid=281`：`bet365`
- `area=皇`：`crown`

每家供应商分别保存：

- 欧指：主胜、平局、客胜
- 让球：主队水位、盘口、客队水位
- 初始值和即时值
- 数据源更新时间与系统抓取时间

现有 `odds_snapshots` 继续作为不可变快照表，每家供应商使用独立快照。上下文保留兼容旧模型的单一 `odds`，默认使用 Bet365，缺失时回退皇冠；同时新增 `odds_by_bookmaker` 供页面和赛前分析显示两家数据及实际使用来源。不对两家赔率做无来源的平均。

空赔率、非法盘口或无效水位不覆盖旧数据。同样的供应商值和源更新时间不重复写入快照，手动同步在无变化时返回明确状态。

## 标识与规范化

- 优先用懂球帝 `match_id` 建立比赛来源映射；没有映射时用赛事、开赛时间和标准化主客队名称匹配。
- 保存懂球帝页面 ID、接口内部 ID 和系统 canonical ID，避免球队 ID 命名空间冲突。
- 已知赛事映射到现有 league key；未知赛事先缓存并标记为未映射，不自动进入下注模型。
- 球员名称进入 API、页面和日志前继续通过 `to_chinese_player_name`。

## 数据库与状态

复用 `fixtures`、`evidence_snapshots`、`odds_snapshots`、`team_snapshots` 和 `job_runs`。新增懂球帝比赛同步状态，用于记录：

```text
source_match_id
initial_analysis_synced_at
initial_odds_synced_at
prematch_analysis_synced_at
prematch_odds_synced_at
last_sync_status
last_sync_error
```

状态更新必须幂等；远程失败只记录失败，不清空已有缓存或快照。

## 失败处理与自动任务

- 赛程任务以“当天成功”为幂等条件，失败在当天允许重试。
- 比赛 enrichment 任务只处理未完成的首次阶段和开赛前 50 分钟窗口。
- 请求使用超时、有限重试、429 退避和低并发；4xx 权限错误不循环重试。
- 自动任务和手动任务共用 provider、解析器和状态锁，避免并发覆盖。
- 所有任务记录成功、部分成功、失败、错误原因和最后更新时间。

## 页面行为

- 赛程列表显示懂球帝来源和同步时间。
- 比赛详情的赔率区同时展示 Bet365、皇冠的欧指和让球，初始/即时分组显示。
- 赛前分析区显示懂球帝来源和快照时间。
- 管理页提供“同步懂球帝赛程”；比赛详情提供“同步赔率与赛前分析”。
- 同步进行中禁用按钮并显示失败或“数据未变化”结果。

## 验证

- 解析测试覆盖 Bet365/皇冠欧指、让球、初始/即时值和盘口格式。
- 映射测试覆盖赛事、比赛和球队 ID 冲突及中文名称转换。
- 同步策略测试覆盖每日一次、首次 enrichment、开赛前 50 分钟、失败重试和手动强制同步的幂等性。
- 数据质量测试确保空赔率、非法字段和接口超时不会覆盖旧数据。
- API 测试验证双供应商进入赛前分析，并返回实际使用的供应商。
- CI 使用 HTTP mock，不直接依赖懂球帝实时站点；完成后运行相关后端测试和前端 lint/build。

## 合规边界

懂球帝公开用户协议限制复制、拷贝、转售及其他商业用途；生产环境和商业展示需要取得相应书面授权。实现仅面向经授权的数据同步，不抓取付费专家方案或绕过访问控制。
